## Description

Monitors Audiocodes session border controllers: CPU and memory usage, hardware health, uptime and call statistics such as active, established and failed inbound and outbound calls.

The plugin pack provides these checks:

* [CPU](#network-audiocodes-snmp-cpu)
* [Hardware](#network-audiocodes-snmp-hardware)
* [Memory](#network-audiocodes-snmp-memory)
* [SBC calls](#network-audiocodes-snmp-sbc-calls)
* [Uptime](#os-linux-snmp-uptime)

### Hardware {/* #network-audiocodes-snmp-hardware */}

</summary>

#### Macros

<div className="plugin-pack-macros">

| Macro | Default value | Description |
|-------|---------------|-------------|
| `COMPONENT` |  | Which component to check (Default: '.*'). Can be: 'fantray', 'module', 'psu' |
| `FILTER` |  | Exclude some parts (comma seperated list) (Example: --filter=fan --filter=psu) Can also exclude specific instance: --filter=fantray,1 |
| `THRESHOLD-OVERLOAD` |  | Set to overload default threshold values (syntax: section,[instance,]status,regexp) It used before default thresholds (order stays). Example: --threshold-overload='psu,CRITICAL,^(?!(cleared)$)' |
| `ABSENT-PROBLEM` |  | Return an error if a component is not 'present' (default is skipping). It can be set globally or for a specific instance: --absent-problem='component_name' or --absent-problem='component_name,instance_value' |
| `NO-COMPONENT` |  | Define the expected status if no components are found (default: critical) |

</div>

</details>
