## Description

Monitors Cisco Prime through its API: the access points it manages.

The plugin pack provides these checks:

* [AP usage](#network-cisco-prime-restapi-ap-usage)

#### Macros

<div className="plugin-pack-macros">

| Macro | Default value | Description |
|-------|---------------|-------------|
| `FILETR-AP` | `.*` | Filter ap name (can be a regexp) |
| `FILTER-CONTROLLER` | `.*` | Filter controller name (can be a regexp) |
| `WARNING-AP-STATUS` | `'%{admin_status} =~ /enable/i && %{status} =~ /minor\|warning/i'` | Set warning threshold for status (Default: '%\{admin_status\} =~ /enable/i && %\{status\} =~ /minor\|warning/i') Can used special variables like: %\{name\}, %\{status\}, %\{controller\}, %\{admin_status\} |
| `CRITICAL-AP-STATUS` | `'%{admin_status} =~ /enable/i && %{status} =~ /major\|critical/i'` | Set critical threshold for status (Default: '%\{admin_status\} =~ /enable/i && %\{status\} =~ /major\|critical/i'). Can used special variables like: %\{name\}, %\{status\}, %\{controller\}, %\{admin_status\} |
| `WARNING-AP-UPTIME` | `1800:` | Warning threshold AP uptime |
| `CRITICAL-AP-UPTIME` | `900:` | Critical threshold AP uptime |
| `WARNING-AP-CLIENTS` |  | Warning threshold AP clients |
| `WARNING-AP-LWAPPUPTIME` |  | Warning threshold AP lwapp uptime |
| `WARNING-CTRL-AP-COUNT` |  | Warning threshold Controller AP count |
| `CRITICAL-AP-CLIENTS` |  | Critical threshold AP clients |
| `CRITICAL-AP-LWAPPUPTIME` |  | Critical threshold AP lwapp uptime |
| `CRITICAL-CTRL-AP-COUNT` |  | Critical threshold Controller AP count |

</div>
