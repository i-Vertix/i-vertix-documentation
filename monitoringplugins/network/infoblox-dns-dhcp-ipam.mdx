## Description

Monitors Infoblox appliances through SNMP: DHCP and DNS usage, system and service status, and interfaces.

The plugin pack provides these checks:

* [DHCP usage](#network-infoblox-snmp-dhcp-usage)
* [DNS Usage](#network-infoblox-snmp-dns-usage)
* [Interfaces](#network-infoblox-snmp-interfaces)
* [Services](#network-infoblox-snmp-services)
* [System](#network-infoblox-snmp-system)
* [Uptime](#os-linux-snmp-uptime)

## Discovery

### Service Discovery

The service discovery creates one service per discovered object, with these rules:

| Service template | Service name |
|------------------|--------------|
| [DHCP usage](#network-infoblox-snmp-dhcp-usage) | `DHCP usage - <name>` |
| [Interfaces](#network-infoblox-snmp-interfaces) | `Interface - <name>` |

See [Service Discovery](/monitoring/monitoring-resources/discovery/service-discovery) for how to run it.

### Services {/* #network-infoblox-snmp-services */}

</summary>

#### Macros

<div className="plugin-pack-macros">

| Macro | Default value | Description |
|-------|---------------|-------------|
| `COMPONENT` |  | Which component to check (Default: '.*'). Can be: 'service' |
| `FILTER` |  | Filter component instances (syntax: component,regexp_filter). Component instances are excluded if matching regexp_filter. E.g: --filter=service,fan1 |
| `THRESHOLD-OVERLOAD` |  | Set to overload default threshold values (syntax: section,[instance,]status,regexp) It used before default thresholds (order stays). Example: --threshold-overload='service,OK,warning' |
| `CRITICAL` |  | Define the critical threshold for temperatures (syntax: type,instance,threshold) Example: --critical='temperature,.*,40' |
| `NO-COMPONENT` |  | Define the expected status if no components are found (default: critical) |
| `WARNING` |  | Define the warning threshold for temperatures (syntax: type,instance,threshold) Example: --warning='temperature,.*,30' |

</div>

</details>
