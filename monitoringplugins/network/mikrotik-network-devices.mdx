## Description

Monitors MikroTik RouterOS devices through SNMP: CPU, memory and disk usage, environment, firmware, interfaces, NTP time, and LTE interfaces, status and signal quality.

The plugin pack provides these checks:

* [CPU](#network-mikrotik-snmp-cpu)
* [Disk](#network-mikrotik-snmp-disk)
* [Environment](#network-mikrotik-snmp-environment)
* [Firmware](#network-mikrotik-snmp-firmware)
* [Interfaces](#network-mikrotik-snmp-interfaces)
* [LTE interfaces](#network-mikrotik-snmp-lte-interfaces)
* [LTE status](#network-mikrotik-snmp-lte)
* [Memory](#network-mikrotik-snmp-memory)
* [NTP-time](#network-mikrotik-snmp-time)
* [Signal](#network-mikrotik-snmp-singal)
* [Uptime](#network-mikrotik-snmp-uptime)

## Discovery

### Host Discovery

The hosts of this plugin pack are found by these host discoveries:

* [Network Topology Discovery](/monitoring/monitoring-resources/discovery/nedi)

### Service Discovery

The service discovery creates one service per discovered object, with these rules:

| Service template | Service name |
|------------------|--------------|
| [Interfaces](#network-mikrotik-snmp-interfaces) | `Interface - <name>` |
| [LTE interfaces](#network-mikrotik-snmp-lte-interfaces) | `Interface - <name>` |

See [Service Discovery](/monitoring/monitoring-resources/discovery/service-discovery) for how to run it.

### Environment {/* #network-mikrotik-snmp-environment */}

</summary>

#### Macros

<div className="plugin-pack-macros">

| Macro | Default value | Description |
|-------|---------------|-------------|
| `COMPONENT` | `.*` | Which component to check (Default: '.*'). Can be: 'current', 'fan', 'psu', 'temperature', 'voltage' |
| `FILTER` |  | Exclude some parts (comma seperated list) (Example: --filter=fan --filter=voltage) Can also exclude specific instance --filter=fan,1.1 |
| `WARNING` |  | Set warning threshold for 'temperature', 'fan', 'voltage' (syntax: type,regexp,threshold) Example: --warning='temperature,.*,40' |
| `CRITICAL` |  | Set critical threshold for 'temperature', 'fan', 'voltage' (syntax: type,regexp,threshold) Example: --critical='temperature,.*,50' |
| `ABSENT-PROBLEM` |  | Return an error if a component is not 'present' (default is skipping). It can be set globally or for a specific instance: --absent-problem='component_name' or --absent-problem='component_name,instance_value' |
| `NO-COMPONENT` |  | Define the expected status if no components are found (default: critical) |
| `THRESHOLD-OVERLOAD` |  | Use this option to override the status returned by the plugin when the status label matches a regular expression (syntax: section,[instance,]status,regexp). Example: --threshold-overload='xxxxx,CRITICAL,^(?!(normal)$)' |

</div>

</details>
