## Description

Monitors Citrix NetScaler appliances through SNMP: CPU, memory and storage usage, connections, HA and health state, interfaces, certificate expiry and the status and traffic of the virtual servers.

The plugin pack provides these checks:

* [Certificates expire](#network-citrix-netscaler-snmp-certificates-expire)
* [Connections](#network-citrix-netscaler-snmp-connections)
* [CPU](#network-citrix-netscaler-snmp-cpu)
* [HA state](#network-citrix-netscaler-snmp-ha-state)
* [Health state](#network-citrix-netscaler-snmp-health)
* [Interfaces](#network-citrix-netscaler-snmp-interfaces)
* [Memory](#network-citrix-netscaler-snmp-memory)
* [Storage](#network-citrix-netscaler-snmp-storage)
* [Uptime](#network-citrix-netscaler-snmp-uptime)
* [VServer status](#network-citrix-netscaler-vserver-snmp-status)
* [VServer status - Load Balancer](#network-citrix-netscaler-vserver-snmp-status-loadbalanding)
* [VServer status - SSLVPN - Contentswitching](#network-citrix-netscaler-vserver-snmp-status-sslvpn)

## Discovery

### Host Discovery

The hosts of this plugin pack are found by these host discoveries:

* [Network Scan](/monitoring/monitoring-resources/discovery/host-discovery)

### Service Discovery

The service discovery creates one service per discovered object, with these rules:

| Service template | Service name |
|------------------|--------------|
| [Interfaces](#network-citrix-netscaler-snmp-interfaces) | `Interface - <name>` |
| [VServer status](#network-citrix-netscaler-vserver-snmp-status) | `VServer status - <name>` |

See [Service Discovery](/monitoring/monitoring-resources/discovery/service-discovery) for how to run it.

| Macro | Default value | Description |
|-------|---------------|-------------|
| `SNMPCOMMUNITY` |  | SNMP community |
| `SNMPVERSION` |  | SNMP version |

| `SNMPTIMEOUT` |  | Time to wait before sending the request again if no reply has been received, in seconds (default: 1). See also --snmp-retries. |
| `SNMPAUTH-PASSPHRASE` |  | SNMP v3 only: Pass phrase hashed using the authentication protocol defined in the --authprotocol option. |

| `SNMPPRIV-PASSPHRASE` |  | SNMP v3 only: Privacy pass phrase (`privPassword`) to encrypt messages using the protocol defined in the --privprotocol option. |
| `SNMPPRIV-PROTOCOL` |  | SNMP v3 only: Privacy protocol (`privProtocol`) used to encrypt messages. Supported protocols are: DES\|AES and since net-snmp 5.9.1: AES192\|AES192C\|AES256\|AES256C. |

</div>

### Health state {/* #network-citrix-netscaler-snmp-health */}

</summary>

#### Macros

<div className="plugin-pack-macros">

| Macro | Default value | Description |
|-------|---------------|-------------|
| `COMPONENT` | `.*` | Which component to check (Default: '.*'). Can be: 'temperature', 'voltage', 'fanspeed', 'psu' |
| `ALTERNATIVE-STATUS-MAPPING` | `1` | Depending on the Netscaler product, the translation of OID .1.3.6.1.4.1.5951.4.1.1.41.7.1.2 may diverge. |
| `FILTER` |  | Exclude some parts (comma seperated list) (Example: --filter=psu) Can also exclude specific instance: --filter=fan,1 |
| `WARNING` |  | Set warning threshold for 'temperature', 'fanspeed', 'voltage' (syntax: type,regexp,threshold) Example: --warning='temperature,.,30' |
| `CRITICAL` |  | Set critical threshold for 'temperature', 'fanspeed', 'voltage'(syntax: type,regexp,threshold) Example: --critical='temperature,.*,40' |
| `THRESHOLD-OVERLOAD` |  | Set to overload default threshold values (syntax: section,[instance,]status,regexp) It used before default thresholds (order stays). Example: --threshold-overload='psu,CRITICAL,^(?!(normal)$)' |
| `ABSENT-PROBLEM` |  | Return an error if a component is not 'present' (default is skipping). It can be set globally or for a specific instance: --absent-problem='component_name' or --absent-problem='component_name,instance_value' |
| `NO-COMPONENT` |  | Define the expected status if no components are found (default: critical) |

</div>

</details>
