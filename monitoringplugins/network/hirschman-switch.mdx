## Description

Monitors Hirschmann switches through SNMP: CPU and memory usage, running processes, hardware health, configuration status, interfaces and uptime.

The plugin pack provides these checks:

* [Configuration](#network-hirschmann-standard-snmp-configuration)
* [CPU](#network-hirschmann-standard-snmp-cpu)
* [Hardware](#network-hirschmann-standard-snmp-hardware)
* [Interfaces](#network-hirschmann-standard-snmp-interfaces)
* [Memory](#network-hirschmann-standard-snmp-memory)
* [Process Count](#network-hirschmann-standard-snmp-processcount)
* [Uptime](#os-linux-snmp-uptime)

## Discovery

### Host Discovery

The hosts of this plugin pack are found by these host discoveries:

* [Network Topology Discovery](/monitoring/monitoring-resources/discovery/nedi)

### Service Discovery

The service discovery creates one service per discovered object, with these rules:

| Service template | Service name |
|------------------|--------------|
| [Interfaces](#network-hirschmann-standard-snmp-interfaces) | `Interfaces - <name>` |

See [Service Discovery](/monitoring/monitoring-resources/discovery/service-discovery) for how to run it.

#### Macros

<div className="plugin-pack-macros">

| Macro | Default value | Description |
|-------|---------------|-------------|
| `COMPONENT` | `.*` | Which component to check (Default: '.*'). Can be: 'fan', 'psu', 'temperature', 'led' |
| `FILTER` |  | Exclude some parts (comma seperated list) (Example: --filter=fan) Can also exclude specific instance: --filter=fan,1.1 |
| `WARNING` |  | Set warning threshold for temperatures (syntax: type,regexp,threshold) Example: --warning='temperature,.*,30' |
| `CRITICAL` |  | Set critical threshold for temperatures (syntax: type,regexp,threshold) Example: --critical='temperature,.*,40' |
| `THRESHOLD-OVERLOAD` |  | Set to overload default threshold values (syntax: section,[instance,]status,regexp) It used before default thresholds (order stays). Example: --threshold-overload='psu,CRITICAL,^(?!(ok)$)' |
| `ABSENT-PROBLEM` |  | Return an error if a component is not 'present' (default is skipping). It can be set globally or for a specific instance: --absent-problem='component_name' or --absent-problem='component_name,instance_value' |
| `NO-COMPONENT` |  | Define the expected status if no components are found (default: critical) |

</div>

    - Option `--warning` changed from `--warning='$_SERVICEWARNING$'` to `--warning=$_SERVICEWARNING$`
    - Option `--critical` changed from `--critical='$_SERVICECRITICAL$'` to `--critical=$_SERVICECRITICAL$`

    - Option `--no-component=$_SERVICENO-COMPONENT$` added
    - Macro `ABSENT-PROBLEM` added
    - Macro `NO-COMPONENT` added
