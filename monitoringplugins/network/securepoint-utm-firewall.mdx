## Description

Monitors Securepoint UTM firewalls through SNMP: CPU, memory, load and storage, interfaces, cluster status, IPsec, OpenVPN and WireGuard tunnels, alerts, applications, processes and sensors.

The plugin pack provides these checks:

* [Alerts](#network-securepoint-utm-snmp-alerts)
* [Applications](#network-securepoint-utm-snmp-applications)
* [ARP](#network-securepoint-utm-snmp-arp)
* [Cluster status](#network-securepoint-utm-snmp-cluster-state)
* [CPU](#network-securepoint-utm-snmp-cpu)
* [CPU detailed](#network-securepoint-utm-snmp-cpu-detailed)
* [Interfaces](#network-securepoint-utm-snmp-interfaces)
* [IPsec tunnel status](#network-securepoint-utm-snmp-ipsec)
* [Load](#network-securepoint-utm-snmp-load)
* [Memory](#network-securepoint-utm-snmp-memory)
* [NTP](#network-securepoint-utm-snmp-time)
* [OpenVPN tunnel status](#network-securepoint-utm-snmp-openvpn)
* [Process count](#network-securepoint-utm-snmp-processcount)
* [Sensors](#network-securepoint-utm-snmp-sensors)
* [Storage](#network-securepoint-utm-snmp-storage)
* [Uptime](#network-securepoint-utm-snmp-uptime)
* [Wireguard tunnel status](#network-securepoint-utm-snmp-wireguard)

| `CRITICAL-STATUS` | `'%{severity} =~ /emergency\|alert\|critical/'` | Define the conditions to match for the status to be CRITICAL (default: ''). You can use the following variables: %\{severity\}, %\{date\}, %\{since\} (seconds), %\{program\}, %\{collector\}, %\{message\} Example: --critical-status='%\{severity\} =~ /emergency\|alert\|critical/ and %\{since\} &lt; 3600' |
