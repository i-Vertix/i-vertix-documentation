## Description

Monitors the expiration of domain names through WHOIS queries and reports the response time of the WHOIS server.

The plugin pack provides these checks:

* [WHOIS Domain expiration](#apps-protocols-whois-domain)

#### Macros

<div className="plugin-pack-macros">

| Macro | Default value | Description |
|-------|---------------|-------------|
| `UNIT` | `d` | Select the unit for expires threshold. May be 's' for seconds, 'm' for minutes, 'h' for hours, 'd' for days, 'w' for weeks. Default is seconds |
| `WARNING-RESPONSE-TIME` | `250` | Warning threshold response time (ms) |
| `WARNING-EXPIRES` | `30:` | Warning threshold expiration |
| `CRITICAL-RESPONSE-TIME` | `500` | Critical threshold response time (ms) |
| `CRITICAL-EXPIRES` | `10:` | Critical threshold expiration |
| `DOMAIN` |  | Domain to check |
| `WHOIS-SERVER` |  | Query this specific whois server host (optional) |
| `EXPIREATION-DATE` |  | Set your domain expiration date manually (Format: YYYY-MM-DD) |
| `UNKNOWN-STATUS` |  | Define the conditions to match for the status to be CRITICAL (Default: '%\{status\} =~ /checkError/i'). You can use the following variables: %\{status\}, %\{domain\} |
| `WARNING-STATUS` |  | Define the conditions to match for the status to be WARNING. You can use the following variables: %\{status\}, %\{domain\} |
| `CRITICAL-STATUS` |  | Define the conditions to match for the status to be CRITICAL. You can use the following variables: %\{status\}, %\{domain\} |

</div>
