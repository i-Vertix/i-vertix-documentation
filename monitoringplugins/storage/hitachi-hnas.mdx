## Description

Monitors Hitachi HNAS storage: cluster status, hardware, interfaces, volume usage, virtual volume quotas and uptime.

The plugin pack provides these checks:

* [Cluster status](#storage-hitachi-hnas-snmp-cluster-status)
* [Hardware](#storage-hitachi-hnas-snmp-hardware)
* [Interfaces](#storage-hitachi-hnas-snmp-interfaces)
* [Uptime](#os-linux-snmp-uptime)
* [Virtual Volumes Quota - VVQ](#storage-hitachi-hnas-snmp-virtual-volumes-quotas)
* [Volume usage](#storage-hitachi-hnas-snmp-volume-usage)

## Discovery

### Service Discovery

The service discovery creates one service per discovered object, with these rules:

| Service template | Service name |
|------------------|--------------|
| [Interfaces](#storage-hitachi-hnas-snmp-interfaces) | `Interface - <name>` |
| [Volume usage](#storage-hitachi-hnas-snmp-volume-usage) | `Volume usage - <name>` |

See [Service Discovery](/monitoring/monitoring-resources/discovery/service-discovery) for how to run it.

#### Macros

<div className="plugin-pack-macros">

| Macro | Default value | Description |
|-------|---------------|-------------|
| `NO-COMPONENT` | `critical` | Define the expected status if no components are found (default: critical) |
| `COMPONENT` |  | Which component to check (Default: '.*'). Can be: 'temperature', 'fan', 'psu', 'sysdrive', 'battery' |
| `FILTER` |  | Exclude some parts (comma seperated list) (Example: --filter=sysdrive) Can also exclude specific instance: --filter=sysdrive,1 |
| `WARNING` |  | Set warning threshold (syntax: type,regexp,threshold) Example: --warning='temperature,.*,30' |
| `CRITICAL` |  | Set critical threshold (syntax: type,regexp,threshold) Example: --critical='temperature,.*,40' |
| `THRESHOLD-OVERLOAD` |  | Set to overload default threshold values (syntax: section,[instance,]status,regexp) It used before default thresholds (order stays). Example: --threshold-overload='sysdrive,OK,formatting' |
| `EXTRA-OPTS` |  | Additional options appended to the plugin command line (host level). |

</div>
