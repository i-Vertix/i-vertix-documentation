## Description

Monitors QNAP NAS devices through SNMP: CPU, memory, pool, volume and storage usage, hardware status, interfaces, processes, NTP, upgrade status and uptime.

The plugin pack provides these checks:

* [CPU](#storage-qnap-snmp-cpu)
* [Hardware status](#storage-qnap-snmp-hardware)
* [Interfaces](#storage-qnap-snmp-interfaces)
* [Memory](#storage-qnap-snmp-memory)
* [NTP](#storage-qnap-snmp-time)
* [Pool](#storage-qnap-snmp-pools)
* [Process count](#storage-qnap-snmp-processcount)
* [Storage](#storage-qnap-snmp-storage)
* [Upgrade status](#storage-qnap-snmp-upgrade)
* [Uptime](#storage-qnap-snmp-uptime)
* [Volume usage](#storage-qnap-snmp-volumes)

## Discovery

### Host Discovery

The hosts of this plugin pack are found by these host discoveries:

* [Network Topology Discovery](/monitoring/monitoring-resources/discovery/nedi)
* [Network Scan](/monitoring/monitoring-resources/discovery/host-discovery)

### Service Discovery

The service discovery creates one service per discovered object, with these rules:

| Service template | Service name |
|------------------|--------------|
| [Interfaces](#storage-qnap-snmp-interfaces) | `Interface - <name>` |
| [Process count](#storage-qnap-snmp-processcount) | `Process - <name>` |
| [Storage](#storage-qnap-snmp-storage) | `Storage - <name>` |

See [Service Discovery](/monitoring/monitoring-resources/discovery/service-discovery) for how to run it.

<div className="plugin-pack-macros">

| Macro | Default value | Description |
|-------|---------------|-------------|
| `EXTRA-OPTS` | `--snmp-force-getnext` | Additional options appended to the plugin command line (host level). |
| `WARNING` |  | Set warning threshold for temperatures |
| `CRITICAL` |  | Set critical threshold for temperatures |
| `COMPONENT` |  | Which component to check (Default: '.*'). Can be: 'disk', 'fan', 'mdisk', 'psu', 'raid', 'temperature. |
| `FILTER` |  | Exclude some parts (comma seperated list) (Example: --filter=disk) Can also exclude specific instance: --filter=disk,1 |
| `THRESHOLD-OVERLOAD` |  | Set to overload default threshold values (syntax: section,status,regexp) It used before default thresholds (order stays). Example: --threshold-overload='disk,CRITICAL,^(?!(ready)$)' |
| `ABSENT-PROBLEM` |  | Return an error if a component is not 'present' (default is skipping). It can be set globally or for a specific instance: --absent-problem='component_name' or --absent-problem='component_name,instance_value' |
| `NO-COMPONENT` |  | Define the expected status if no components are found (default: critical) |

</div>

</details>
