## Description

Monitors Synology NAS devices through SNMP: CPU, memory, swap and load, storage, temperature, hardware status, UPS, high availability, interfaces, NTP, upgrade status and uptime.

The plugin pack provides these checks:

* [CPU](#storage-synology-snmp-cpu)
* [HA](#storage-synology-snmp-ha)
* [Hardware status](#storage-synology-snmp-components)
* [Interfaces](#storage-synology-snmp-interfaces)
* [Memory](#storage-synology-snmp-memory)
* [NTP](#storage-synology-snmp-time)
* [Storage](#storage-synology-snmp-storage)
* [Swap](#storage-synology-snmp-swap)
* [System Load](#storage-synology-snmp-load)
* [Temperature](#storage-synology-snmp-temperature)
* [Upgrade status](#storage-synology-snmp-upgrade)
* [UPS](#storage-synology-snmp-ups)
* [Uptime](#storage-synology-snmp-uptime)

## Discovery

### Host Discovery

The hosts of this plugin pack are found by these host discoveries:

* [Network Topology Discovery](/monitoring/monitoring-resources/discovery/nedi)
* [Network Scan](/monitoring/monitoring-resources/discovery/host-discovery)

### Service Discovery

The service discovery creates one service per discovered object, with these rules:

<div className="plugin-pack-templates">

| Service template | Service name |
|------------------|--------------|
| [Interfaces](#storage-synology-snmp-interfaces) | `Interface - <name>` |
| [Storage](#storage-synology-snmp-storage) | `Storage <name>` |

</div>

See [Service Discovery](/monitoring/monitoring-resources/discovery/service-discovery) for how to run it.

| `SNMPTIMEOUT` |  | Time to wait before sending the request again if no reply has been received, in seconds (default: 1). See also --snmp-retries. |

</div>

Macros without a default value are only defined in the check commands. Set them on the host where needed.

<div className="plugin-pack-macros">

| Macro | Default value | Description |
|-------|---------------|-------------|
| `COMPONENT` |  | Which component to check (Default: 'all'). Can be: 'psu', 'fan_cpu', 'fan_psu', 'disk', 'raid', 'system' |
| `FILTER` |  | Exclude some parts (comma seperated list) (Example: --filter=psu) Can also exclude specific instance: --filter=psu,1 |
| `THRESHOLD-OVERLOAD` |  | Set to overload default threshold values (syntax: section,[instance,]status,regexp) It used before default thresholds (order stays). Example: --threshold-overload='psu,CRITICAL,^(?!(on)$)' |
| `CRITICAL` |  | Set critical threshold for 'disk.badsectors' (syntax: type,regexp,threshold) Example: --critical='disk.badsectors,.*,50' |
| `WARNING` |  | Set warning threshold for 'disk.badsectors' (syntax: type,regexp,threshold) Example: --warning='disk.badsectors,.*,30' |

</div>
